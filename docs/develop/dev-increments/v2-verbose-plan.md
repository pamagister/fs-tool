# Mission: Compact Default Output and Global Verbose Mode

## Objective

Reduce the amount of output generated by `fs-tool` by introducing compact default representations for commands that return filesystem entries.

The goal is to make the CLI more efficient and practical for both humans and LLM agents without sacrificing information availability or analysis completeness.

All commands must continue returning the same number of entries as before. Only the fields included in each entry's default representation should change.

A global `--verbose` option must provide access to the complete existing entry information.

**The JSON schema version must remain `1`.**

## Scope and Constraints

### Mandatory scope

- Introduce compact default output profiles for relevant commands.
- Add a globally available `--verbose` option.
- Apply the output profiles consistently to JSON and plain-text output.
- Preserve all entries returned by the existing analysis.
- Preserve existing analysis behavior, completeness semantics, diagnostics and exit codes.
- Keep the JSON envelope and `schema_version: 1`.
- Preserve compatibility with `verify inventory`.
- Update documentation and tests.

### Explicit constraints

- Do not change filesystem scanning or analysis behavior.
- Do not reduce the number of returned entries.
- Do not introduce pagination or output limits.
- Do not calculate additional metadata when `--verbose` is enabled.
- Do not calculate hashes unless explicitly requested through existing options.
- Do not silently omit errors, warnings, unavailable capabilities or incomplete-analysis information.
- Do not change the JSON envelope structure or schema version.

### Non-goals

The following ideas are explicitly deferred:

- Pagination (`--offset`, cursors or similar).
- A separate output limit such as `--limit`.
- User-configurable field selection (`--fields`).
- Additional output profiles such as `--summary`.
- Changes to filesystem scanning limits such as `--max-entries`.
- Changes to the internal filesystem data models unless strictly required by the output implementation.

## Architecture and Decisions

### 1. Separate internal data from output representation

The filesystem core must continue providing complete internal data models.

Output filtering belongs exclusively in the output/serialization layer.

The implementation must not remove information from internal models merely because it is not part of the default output.

This preserves the ability to:
- Use complete metadata internally.
- Add new output profiles later.
- Support different consumers without duplicating filesystem analysis.
- Keep the core independent of CLI and presentation concerns.

### 2. Global `--verbose` option

Introduce a global CLI option:

```bash
fs-tool --verbose inspect inventory /path
fs-tool inspect inventory /path --verbose
```

Both invocation styles should work consistently, subject to the existing CLI argument-parsing architecture.

The option must be available throughout the CLI, not implemented separately for individual commands.

Behavior:

| Mode | Behavior |
|---|---|
| Default | Compact output |
| `--verbose` | Complete existing output fields |
| `--json` | Compact JSON |
| `--json --verbose` | Complete JSON |
| `--plain` | Compact human-readable output |
| `--plain --verbose` | Detailed human-readable output |

Existing `--format auto|json|plain` behavior must remain unchanged.

Both option positions are supported by the existing CLI architecture without duplicating the option on every subcommand: the root callback accepts ``--verbose`` as a global option and stores it in ``CliContext`` (following the existing ``json_output``/``plain_output`` pattern). ``cli._hoist_global_options`` moves known global flags ahead of the command before Click parses them; adding ``"--verbose"`` to ``_GLOBAL_FLAGS`` makes ``fs-tool inspect inventory /path --verbose`` work identically to ``fs-tool --verbose inspect inventory /path``.

`--verbose` changes presentation only. It must not trigger additional filesystem operations, metadata extraction, hashing or content analysis.

For commands that do not return filesystem-entry collections, preserve their existing output behavior unless a meaningful and clearly defined verbose representation already exists.

### 3. Command-specific compact output profiles

Do not apply one generic field-selection rule to every command.

Define compact output profiles according to the purpose of each command.

The following profiles establish the intended default behavior.

#### `inspect tree`

Purpose: Communicate directory structure with minimal output overhead.

Default entry fields:

```json
{
  "rel_path": "documents/report.pdf",
  "type": "file"
}
```

Requirements:
- Include all entries within the existing scan scope.
- Preserve directory hierarchy and deterministic ordering.
- Preserve existing root and count information.
- Do not include file metadata that is irrelevant to understanding the tree structure.

Verbose mode:
- Include all existing entry fields.

#### `inspect inventory`

Purpose: Provide a useful, portable filesystem inventory.

Default entry fields:

```json
{
  "rel_path": "documents/report.pdf",
  "type": "file",
  "extension": ".pdf",
  "size": 245760,
  "modified": "2026-11-11T18:30:00"
}
```

Requirements:
- Include all entries within the existing scan scope.
- Preserve relative paths.
- Preserve fields required by the existing inventory verification workflow.
- Include `sha256` only when requested through the existing `--hash` option.
- Preserve `tree_hash` behavior and its existing conditions.
- Do not include unnecessary filesystem-specific metadata in the compact representation.

Verbose mode:
- Include all existing entry fields.
- Do not calculate hashes or additional metadata merely because verbose mode is enabled.

Verification compatibility: ``verify inventory`` requires ``rel_path`` and ``type`` per entry and reads ``size``, ``target`` and ``sha256`` only when present. The compact profile preserves ``rel_path``, ``type`` and ``size``, so size-mismatch detection continues to work on compact inventories. ``target`` is omitted from the compact profile, so symlink-target changes are not detected when verifying against a compact inventory (verification gracefully skips the check); use ``--hash`` or verbose output when target/hash comparison is required. ``complete`` is preserved at inventory level, so incomplete scans remain visible to verification.

#### `find`

Purpose: Return matching filesystem entries efficiently.

Default entry fields:

```json
{
  "rel_path": "documents/report.pdf",
  "type": "file",
  "size": 245760
}
```

Requirements:
- Include all matches within the existing scan scope.
- Preserve existing matching behavior and ordering.
- Preserve existing root, count and completeness information.
- Avoid redundant absolute paths and unrelated metadata in the compact representation.

Verbose mode:
- Include all existing entry fields.

Plain-text verbose output shows the same reduced information set as JSON verbose mode, using the same per-command field-selection logic, only in the human-readable format: each renderer decides which fields to include in compact versus verbose mode.

#### Other commands

Review commands such as `inspect info` and `inspect analyze`.

Do not unnecessarily reduce information that is essential to their purpose.

Where these commands return filesystem-entry objects, apply the same principle: define a command-specific compact profile and retain the complete representation in verbose mode.

Do not introduce artificial output reduction merely to make every command behave identically.

Scope note: ``inspect info`` returns a single entry with its complete metadata, and ``inspect analyze`` returns an analysis report rather than an entry collection. Neither is a collection of filesystem entries, so no compact output profile is defined for them in this mission; both keep their existing output in default and verbose mode unless a meaningful compact form is defined later.

### 4. Preserve JSON envelope and semantics

The existing JSON envelope must remain unchanged:

```json
{
  "schema_version": 1,
  "success": true,
  "command": "inspect.inventory",
  "result": {},
  "errors": [],
  "warnings": [],
  "complete": true
}
```

Requirements:
- Keep `schema_version` at `1`.
- Preserve existing top-level fields.
- Preserve error and warning structures.
- Preserve exit-code behavior.
- Preserve `complete` semantics.
- Do not interpret compact output as incomplete analysis.

A compact result must still represent the complete result of the requested analysis.

### 5. Preserve inventory verification compatibility

`verify inventory` is an important integration boundary.

The default compact inventory must remain a valid input for the existing verification workflow.

In particular:
- Preserve all fields required by the current verification implementation.
- Preserve relative-path semantics.
- Preserve optional hash behavior.
- Preserve compatibility with existing schema version 1 inventory files.

Do not solve output reduction by removing fields that verification depends on.

If the current implementation requires additional fields, document and preserve those requirements.

## Dependencies, Risks and Open Questions

### Dependencies

- Existing output serializers and renderers.
- Existing CLI argument parsing and execution context.
- Existing filesystem-entry data models.
- Existing `verify inventory` implementation and schema version 1 format.

### Risks and mitigations

**Risk: Verification breaks because compact inventory omits required fields.**

Mitigation: Inspect the actual verification implementation before finalizing the inventory profile. Add integration tests using compact inventory output.

**Risk: Verbose mode accidentally triggers additional analysis.**

Mitigation: Keep verbosity strictly within the presentation layer. Test that hashing and optional analysis are not triggered by `--verbose`.

**Risk: Different commands apply inconsistent output filtering.**

Mitigation: Each command/renderer explicitly defines its own compact field set in a documented profile, and verbose mode always returns the complete existing entry representation; consistency is verified by tests.

**Risk: Incomplete scans become indistinguishable from complete scans.**

Mitigation: Preserve all existing completeness, warning, error and exit-code semantics.

**Risk: Existing consumers rely on fields removed from default output.**

Mitigation: Document the new default behavior, retain all fields through `--verbose`, and keep the JSON envelope and schema version unchanged.

### Settled decisions

- All entries must continue to be returned.
- Only the default information per entry is reduced.
- `--verbose` is globally available.
- Verbose mode returns existing information without additional analysis.
- JSON schema version remains `1`.
- JSON and plain-text output both support compact and verbose representations.
- Hashing remains controlled by existing explicit options.
- Pagination and output limits are outside this mission.
- ``inspect info`` and ``inspect analyze`` keep their existing output in both default and verbose mode.
- Output filtering is decentralized: each command/renderer decides which fields belong in its compact profile versus its complete representation.

### Unresolved implementation details

- Exact compact field sets for commands beyond `inspect tree`, `inspect inventory` and `find` should be determined by reviewing their actual purpose and current output contracts.

`inspect info` and ``inspect analyze`` are excluded from output-profile reduction in this mission. Plain-text verbose output mirrors the JSON compact/verbose field selection using the same per-command logic, only in the human-readable format. The filtering mechanism is decentralized: each command/renderer decides which fields belong in its compact profile.
